## 已确认范围

- [x] VNext-34-A 编辑态拖拽稳定性优化
  说明：
  围绕 2026-04-29 的拖拽稳定性反馈，排查并优化编辑态元素拖动时的抖动与回跳问题。
  来源：
  2026-04-29 用户新增需求
  需求拆分：
  1. 编辑态拖拽 `Text / Image / Rect` 时，不再出现明显抖动、回跳或位置反复震荡。
  2. 拖拽经过吸附阈值区域时，位置反馈保持连续，不因吸附判断滞后一帧而出现来回跳动。
  3. 拖拽释放后，自动保存与刷新恢复结果保持正确。

- [x] VNext-34-B slide 卡片交互与右键菜单
  说明：
  优化左侧 slide 卡片交互体验，并新增卡片级右键菜单，把常用页面管理入口收敛到当前操作上下文。
  来源：
  2026-04-29 用户新增需求
  需求拆分：
  1. slide 卡片 hover、选中与右键呼出反馈更明确，页面管理入口更集中。
  2. 右键菜单中展示“后插入”“复制”“删除”三个常用操作。
  3. “删除”操作需带弹窗二次确认，并保持现有拖拽排序链路不受影响。

- [x] VNext-34-C 预览页布局与信息架构联合优化
  说明：
  把预览态相关布局与信息问题作为同一轮工作统一处理，释放中心课件区域空间并收敛非核心信息。
  来源：
  2026-04-29 用户新增需求
  需求拆分：
  1. 压缩预览态 slide 卡片高度与纵向占比，避免列表继续吃掉主预览区空间。
  2. 提升中心课件区域的可用高度，保证常见桌面视口下课件画面更完整。
  3. 中心区域只保留课件本身，把步骤说明或辅助信息移出主预览区。

## 当前执行版本：VNext-35

### 版本目标

- 在 `VNext-34` 完成页面管理与预览布局收口后，下一轮重点转向“编辑效率提升”“时间轴编排提效”和“预览沉浸感增强”。
- 本轮按用户要求，在现有需求池之外补充 5 个候选需求与优化项，先进入版本规划，不提前写入当前执行池。
- 所有候选项默认按“基础版”控制范围，不扩展到协同编辑、远程存储、多引擎或复杂富文本能力。

### 已确认候选范围

- [x] VNext-35-A 画布缩放与视图控制
  说明：
  补齐编辑态与预览态的视图缩放能力，让用户在常见桌面视口下更高效地查看大尺寸或细节内容。
  来源：
  2026-04-29 用户要求在需求池之外补充下一版本规划
  需求拆分：
  1. 支持放大、缩小、适配画布与恢复 `100%` 四类基础视图操作。
  2. 在工作台中明确展示当前缩放比例，并允许快速回到默认视图。
  3. 缩放能力保持 UI 层与事件层解耦，不直接把视图状态耦合到 Fabric 组件本地逻辑中。

- [x] VNext-35-B 多选、框选与批量对齐基础版
  说明：
  提升编辑态批量排版效率，减少逐个对象调整位置的重复操作。
  来源：
  2026-04-29 用户要求在需求池之外补充下一版本规划
  需求拆分：
  1. 支持 `Shift` 多选与拖拽框选当前 slide 中的多个对象。
  2. 支持基础批量对齐能力，至少覆盖左对齐、水平居中、顶部对齐与垂直居中。
  3. 批量操作后的选中态、自动保存与刷新恢复结果保持一致。

- [x] VNext-35-C 时间轴编排效率优化
  说明：
  在现有时间轴功能可用的基础上，进一步降低步骤配置与维护成本。
  来源：
  2026-04-29 用户要求在需求池之外补充下一版本规划
  需求拆分：
  1. 支持步骤列表的折叠、展开与更清晰的触发方式摘要展示。
  2. 支持步骤复制或基于当前步骤快速新增，减少重复配置。
  3. 触发对象、目标对象与动画类型的对应关系在列表中可快速识别。

- [x] VNext-35-D 预览态沉浸式播放控制
  说明：
  让播放态更接近真实课件演示场景，减少非核心 UI 对课件画面的干扰。
  来源：
  2026-04-29 用户要求在需求池之外补充下一版本规划
  需求拆分：
  1. 支持键盘控制播放，至少覆盖下一步、上一步与重播当前页。
  2. 支持全屏预览或等价的沉浸式播放模式。
  3. 进入沉浸式播放后，主区域默认只突出课件内容，辅助信息降级展示。

- [x] VNext-35-E 项目列表检索与排序优化
  说明：
  提升项目数增多后的查找效率，避免项目列表成为后续使用门槛。
  来源：
  2026-04-29 用户要求在需求池之外补充下一版本规划
  需求拆分：
  1. 支持按项目标题搜索与按最近修改时间排序。
  2. 列表卡片补充更明确的最后编辑时间表达，便于快速识别最近项目。
  3. 搜索、排序与进入项目链路需保持现有本地持久化模型兼容。

- 下一版本仍需遵守 `docs/PRD.md` 中定义的架构边界，尤其保持 UI 层与事件层解耦、文档模型与渲染引擎解耦。

## 下一执行版本：VNext-36

### 版本目标

- 在 `VNext-35` 完成基础效率补齐后，下一轮继续聚焦“批量编辑效率提升”“时间轴维护成本下降”“项目恢复能力增强”和“资源链路健壮性补齐”。
- 本轮至少纳入 5 项可执行的新功能或优化，优先选择已有测试遗留点、已完成版本中的后续方向，以及不会破坏现有架构边界的增强项。
- 所有能力仍按 MVP 延展思路控制范围，不扩展到富文本、协同编辑、远程存储、多引擎并行接入或复杂媒体系统。

### 已确认候选范围

- [ ] VNext-36-A 多选批量操作增强
  说明：
  在现有多选、框选与基础对齐能力之上，补齐高频批量操作缺口，减少逐个对象处理的往返成本。
  来源：
  2026-05-08 用户要求规划下一版本，且现有测试报告已多次标记多选复制、批量删除与更多批量场景仍待补齐。
  需求拆分：
  1. 支持多选对象的批量删除、批量复制 / 粘贴 / 重复，并保持单次批量操作对应单次撤销 / 重做。
  2. 在已有基础对齐之外，补齐水平分布、垂直分布等高频排版操作，并保证几何结果、自动保存与刷新恢复一致。
  3. 批量操作需继续通过标准命令层落地，不得在 Fabric 适配器或 Vue 组件中直接分散改写单节点状态。

- [ ] VNext-36-B 时间轴编排二次提效
  说明：
  在 `VNext-35-C` 的折叠、复制和摘要能力基础上，继续降低长时间轴维护成本。
  来源：
  2026-05-08 用户要求规划下一版本，且 `VNext-35-C` 测试已明确建议补充拖拽排序与折叠态持久化。
  需求拆分：
  1. 支持时间轴步骤拖拽排序，并通过标准命令层写回当前 slide 的步骤顺序。
  2. 支持多 slide 切换、刷新恢复后的步骤折叠态保持，避免时间轴长列表反复手动展开。
  3. 支持步骤级批量展开 / 收起后的状态回显与摘要同步，保持长时间轴下的可识别性。

- [ ] VNext-36-C 项目列表管理升级
  说明：
  在 `VNext-35-E` 的搜索与时间排序基础上，进一步提升项目数量增多后的整理与恢复效率。
  来源：
  2026-05-08 用户要求规划下一版本，且最近项目列表优化已留出更多排序与恢复类增强空间。
  需求拆分：
  1. 支持按项目标题之外的更多维度排序，至少补齐按创建时间与页面数量的排序入口。
  2. 支持项目列表排序偏好在本地持久化，刷新后保留用户最近一次选择。
  3. 支持项目归档前的恢复辅助信息展示，例如更清晰的尺寸 / 页数摘要与最近编辑状态，减少打开前试错成本。

- [ ] VNext-36-D 图片与背景资源链路健壮性补齐
  说明：
  在本地图片资产持久化已稳定的基础上，继续补齐远程资源与混合资源场景的可用性。
  来源：
  2026-05-08 用户要求规划下一版本，且背景图、图片资源和资产仓库相关测试均保留了远程 URL 与混合资源回归空缺。
  需求拆分：
  1. 支持远程图片 URL 作为图片节点或背景图来源，并保持编辑态、预览态、缩略图与导出链路表达一致。
  2. 补齐远程 URL 与本地 `cw-asset://` 资产混用时的加载、保存、导出与恢复规则，避免资源来源混杂后行为不一致。
  3. 当资源加载失败或资产缺失时，给出明确反馈并保留最近诊断日志可追踪性，不静默吞掉异常。

- [ ] VNext-36-E 预览态播放体验增强
  说明：
  在沉浸式播放和基础键盘控制之外，继续补齐真实演示场景下的导航与恢复能力。
  来源：
  2026-05-08 用户要求规划下一版本，且预览体验仍有进一步贴近真实课件演示的空间。
  需求拆分：
  1. 支持按 slide 维度的播放进度提示，帮助用户在多页课件中识别当前页与当前步骤位置。
  2. 支持更明确的播放结束状态与重新开始入口，减少用户在演示尾部的操作迷失。
  3. 继续保持预览区“课件内容优先”，新增状态信息需轻量展示，避免重新挤占主画布区域。

- [ ] VNext-36-F 自动保存与恢复韧性优化
  说明：
  围绕当前已具备的自动保存、图片资产仓库和诊断日志能力，继续提升异常恢复体验。
  来源：
  2026-05-08 用户要求规划下一版本，且资源仓库与自动保存测试已明确保留 IndexedDB 异常、缺失资产与恢复体验空缺。
  需求拆分：
  1. 当本地资产仓库不可用、被清空或恢复失败时，工作台需给出明确状态反馈，而不是仅在诊断日志中留痕。
  2. 支持在项目打开阶段展示更清晰的恢复结果摘要，区分“已完整恢复”“部分资源缺失”“需要重新选择资源”等状态。
  3. 自动保存异常与恢复异常仍需复用统一 logger，避免新增一套独立的临时错误提示机制。

- 所有增强仍按 MVP 延展思路控制范围，不扩展到富文本、表格图表、音视频、协同编辑或复杂动画系统。

### VNext-38 已确认范围

#### 最高优先级：编辑稳定性缺陷修复

- [x] BUG-VNEXT38-01 多选旋转后拖拽导致旋转状态回退
  说明：
  修复多选元素统一旋转后，再拖拽其中任一元素时，其余已旋转元素被重置到旋转前几何状态的问题；当前先通过禁用多选旋转来移除这条不稳定交互链路。
  来源：
  2026-05-15 用户新增缺陷需求：“多选元素旋转时，再拖拽某个元素，会出现所有被旋转的元素被重置为旋转之前的状态”
  需求拆分：
  1. 多选旋转结束后，所有参与节点的最新旋转角度与几何结果都必须完整写回当前文档状态
  2. 后续拖拽单个元素时，不得覆盖或回退其他已完成批量旋转的节点状态
  3. 自动保存、刷新恢复与再次选中后，旋转后的结果必须保持一致
  实施边界：
  - 聚焦多选旋转后的拖拽回退链路，不扩展到无关批量对齐、分布或快捷键重构
  - 优先排查多选旋转提交、单节点拖拽同步与编辑态持久化之间的状态覆盖问题
  - 允许直接收口多选旋转入口，不强行兼容旧的批量旋转交互
  完成情况：
  已于 2026-05-19 完成。当前已在编辑态统一禁用 `ActiveSelection` 多选旋转，移除批量旋转手柄与旋转能力，避免继续暴露不稳定链路；同时保留多选拖拽和单节点旋转能力，并更新 `pnpm test:bug-vnext38-01` 覆盖“多选禁旋策略 -> 多选拖拽 -> 单节点拖拽 -> 自动保存 -> 刷新恢复”链路，联动回归 `pnpm test:bug-rotate-drift`。已通过 `pnpm typecheck`、`pnpm build`、`pnpm test:bug-vnext38-01` 与 `pnpm test:bug-rotate-drift`。

#### 第一优先级：元素基础属性补全

- [x] VNext-38-A Text 元素属性增强
  说明：
  补齐 Text 元素的核心样式属性，让文本编辑达到基础设计工具标准。
  来源：
  2026-05-11 用户要求"先做好基础能力"，系统梳理后确认 Text 元素当前缺失多项核心属性
  需求拆分：
  1. 字体选择：支持系统字体列表（至少包含 Arial、Times New Roman、Courier New、微软雅黑、宋体、黑体）
  2. 文本对齐：左对齐/居中/右对齐/两端对齐
  3. 行高控制：支持 1.0 - 3.0 倍行高，默认 1.5
  4. 透明度：支持 0-100% 透明度调节
  5. 旋转角度：支持 -180° 到 180° 旋转，显示旋转手柄
  实施边界：
  - 扩展 `packages/core/src/schema.ts` 中 Text 节点的 schema 定义
  - 在 `packages/fabric/src/editor-adapter.ts` 中补齐 Fabric Text 对象的属性映射
  - 在 `packages/vue/src/editor/PropertyPanel.vue` 中补齐对应的属性编辑控件
  - 保持现有文本双击编辑、浮动工具条与自动保存逻辑不变
  - 字体选择需考虑字体加载失败的降级方案
  完成情况：
  已于 2026-05-15 完成。当前已拆出独立 `InspectorTextSection` 收口文本属性面板，补齐字体预设、两端对齐、行高调节与字体缺失降级提示；同时贯通 Text 节点默认值、schema 解析与刷新恢复链路，并新增 `pnpm test:vnext-38-a` 覆盖“编辑 -> 自动保存 -> 刷新回显”专项回归。已通过 `pnpm typecheck`、`pnpm build` 与 `pnpm test:vnext-38-a`。

- `VNext-38` 仍需遵守 `docs/PRD.md` 中定义的架构边界，尤其是 UI 层与事件层解耦、文档模型与渲染引擎解耦。

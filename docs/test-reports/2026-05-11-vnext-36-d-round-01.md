## 测试结果

- 结论：通过
- 同源远程背景图与本地 `cw-asset://` 图片可在同一项目内混用；保存后项目存储继续保留远程背景 URL，图片节点继续写入 `cw-asset://` 内部资产引用。
- 导出 JSON 后，远程背景图继续保留原始 URL，本地图片会恢复为标准 `data:image/...`，未泄漏 `cw-asset://` 内部协议。
- 刷新工作台后，运行时文档会继续保留远程背景 URL，并把本地图片重新恢复成可直接渲染的 `data URL`，说明“混合资源存储 + 运行时恢复”链路稳定可用。
- 当图片节点切换到无 CORS 的远程图片时，项目保存不会失败；顶栏会显示“当前页面已保存，但本页资源暂时无法生成封面截图...”警告，同时诊断日志中可追到 `editor.thumbnail.capture.failed` 与 `project.thumbnail.capture.skipped`。
- `VNext-32-D` 旧资产链路在当前版本服务 `http://127.0.0.1:32174/projects` 下继续通过：本地图片仍会写入 `cw-asset://`，换图后旧资产可清理，导出仍恢复为标准 `data URL`，删除项目后资产仓库会清空。

## 未覆盖范围与剩余风险

- 本轮重点覆盖图片节点与背景图的远程 URL / 本地资产混用、缩略图失败降级与旧资产回归，未覆盖超大图片、慢网速长时加载或多页同时引用大量远程资源的压力场景。
- 无 CORS 远程图片当前策略是“优先尝试安全加载，失败后回退为可显示但不可安全截图”；因此保存与预览可继续，但项目封面和页面缩略图可能不会更新为最新画面。
- 本轮未覆盖远程服务间歇性超时、302 跳转链较长或远程地址在预览态播放过程中中途失效的场景；如后续继续扩展资源链路，建议补充更细粒度的异常恢复测试。
